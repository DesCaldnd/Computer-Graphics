# 29. UI: отладочный оверлей и игровой интерфейс

> Модуль `ui` (таргет `Oxwald::ui`, пространство имён `ox::ui`, зонтичный заголовок `<oxwald/ui/ui.hpp>`). Два слоя интерфейса: отладочный оверлей на Dear ImGui 1.92 (с докингом) и игровой UI на RmlUi 6.2 (HTML/CSS-подобные документы). Оба рисует одна render-фича рендерера в точке `Overlay`. Зависит от `render` и `runtime`. Если при сборке есть `script`, `async` и `gameplay`, появляются Lua-таблицы `ui`/`debug`, список корутин и переключатели отладочной отрисовки.

## Зачем

В игре нужны два разных интерфейса:

| Задача | Что есть |
| --- | --- |
| Отладка во время игры | Оверлей ImGui по **F1** или **`~`**: статистика кадра и GPU-пассов, консоль, уровни качества и cvar'ы, инспектор сущностей, просмотр render graph, корутины, отладочная отрисовка |
| Свои инструменты разработчика | Окна ImGui из C++ (`addWindow`, прямые вызовы `ImGui::*`) и из Lua (`debug.window`, `debug.sliderFloat`, …) |
| Игровые меню и HUD | Документы `.rml` + стили `.rcss` на RmlUi: вёрстка, анимации переходов, шрифты с кириллицей |
| Связь UI и данных игры | Модели данных (data bindings): `{{health}}`, `data-if`, `data-for`, `data-class-*`, `data-event-click` — из C++ и Lua |
| Быстрые итерации | Hot reload: правка `.rml`/`.rcss` применяется без перезапуска игры |
| Меню настроек графики | Готовая модель данных `settings` над `ox::Settings` и образец `settings.rml`: качество Low–Ultra/Auto, окно, разрешение, VSync, RT, апскейлер, громкость |

Ни у ImGui, ни у RmlUi нет своего бэкенда Vulkan или OpenGL. Ввод приходит из `ox::InputEvent`, геометрия обоих слоёв собирается в общий `UiFrame` и рисуется собственным пайплайном через rhi.

## Ключевые понятия

| Понятие | Что это |
| --- | --- |
| `UiModule` | Модуль движка (`IEngineModule`): регистрирует сервис `UiSystem`, фильтр ввода, отладочные окна, модель `settings`, Lua-API и консольные команды `ui.*` |
| `withUi(renderer)` | Обёртка над рендерером из `render::createRenderer()`: добавляет UI-фичу и запускает бенчмарк «Auto» между кадрами |
| `UiSystem` | Сервис модуля: владеет `ImGuiLayer`, `GameUI`, `DebugTools` и `UiRenderBridge`, маршрутизирует ввод, публикует один `UiFrame` за кадр |
| `ImGuiLayer` | Свой контекст ImGui, шрифты Inter и JetBrains Mono, оверлей (меню, док-область, окна инструментов) |
| `DebugTools` | Встроенные окна: Stats, Console, Settings & CVars, Entity Inspector, Render Graph, Coroutines, Debug Draw |
| `GameUI` | RmlUi: один контекст `"game"`, документы по имени, модели данных, обработчики событий, локализация, hot reload |
| Документ | Файл `.rml`, загруженный `GameUI::load`. Его **имя** — путь, переданный в `load` (`"hud.rml"`) |
| Модель данных | `Rml::DataModelConstructor` / Lua `ui.createModel`: переменные и события, на которые ссылается документ через `data-model="имя"` |
| `UiFrame` | Вершины, индексы и команды отрисовки одного кадра UI в пикселях кадра |
| `UiRenderBridge` | Канал «игровой поток → поток рендера» (последний `UiFrame`, текстуры) и обратно (статистика, `DeviceCaps`, render graph, результат бенчмарка) |
| `UiOverlayFeature` | Render-фича `"UI"`: один графический пасс поверх `SceneColorLDR` в точке `Overlay` (порядок 10000, выше всех) |

### Кадр UI

1. `UiModule::preUpdate` вызывает `UiSystem::beginFrame`: RmlUi `update` + проверка hot reload, ImGui `NewFrame`, отладочные окна.
2. Скрипты и системы игры могут вызывать ImGui (или Lua `debug.*`) в любой момент кадра.
3. По сигналу `Engine::frameEnded` вызывается `endFrame`: RmlUi и ImGui строят геометрию, `UiFrame` публикуется в мост.
4. Поток рендера рисует последний опубликованный кадр. Задержка UI — не больше одного кадра.

## Шаг 1. Подключение к движку

```cpp
#include <oxwald/render/runtime_renderer.hpp>
#include <oxwald/ui/ui.hpp>

ox::Engine engine;
engine.addModule(std::make_unique<ox::ui::UiModule>());                // UiSystem, ввод, Lua, консоль
engine.setRenderer(ox::ui::withUi(ox::render::createRenderer()));      // UI-фича + бенчмарк "Auto"
engine.init(config);

auto* ui = engine.services().tryGet<ox::ui::UiSystem>();
```

OxwaldPlayer делает это сам (кроме выделенного сервера). Если `UiModule` не добавлен, `withUi` пишет предупреждение «no UiSystem service» и UI не рисуется. Если рендерер не из модуля `render`, UI тоже не рисуется.

Настройки модуля передаются в конструктор `UiModule(UiConfig)`:

| Структура | Поле | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `UiConfig` | `imgui`, `gameUI` | `true`, `true` | Включить слой ImGui / игровой UI |
| | `debugTools` | `true` | Зарегистрировать встроенные отладочные окна |
| | `bindSettingsMenu` | `true` | Создать модель данных `settings` над `Engine::settings()` |
| | `headlessSize` | 1280×720 | Размер UI без окна платформы |
| | `cursorScale` | 0 | Множитель координат курсора. 0 = авто: DPI на macOS (GLFW отдаёт точки), 1 на остальных |
| `ImGuiLayerConfig` | `fontSize` | 15 | Логические пиксели (умножаются на DPI) |
| | `docking` | `true` | Докинг окон |
| | `iniPath` | пусто | Файл раскладки окон. `UiModule` подставляет `user://imgui.ini` |
| | `visible` | `false` | Оверлей открыт при старте |
| | `toggleKeys` | `{F1, GraveAccent}` | Клавиши переключения оверлея |
| `GameUIConfig` | `root` | `project://UI/` | Корень для относительных путей документов |
| | `hotReload`, `hotReloadInterval` | `true`, 0.5 с | Опрос времени изменения `.rml/.rcss` |
| | `loadDefaultFonts` | `true` | Inter (обычный и жирный) и JetBrains Mono из ресурсов модуля |
| | `contextName` | `"game"` | Имя контекста RmlUi |

**Консольные команды модуля:**

| Команда | Что делает |
| --- | --- |
| `ui.debug` | Показать или скрыть оверлей (как F1 / `~`) |
| `ui.open <окно>` | Открыть отладочное окно (`ui.open Stats`, `ui.open Render Graph`) и показать оверлей |
| `ui.load <doc.rml>` | Загрузить и показать документ игрового UI |
| `ui.hide <doc.rml>` | Скрыть документ |
| `ui.reload` | Принудительно перезагрузить все документы |
| `ui.ShowStats 1` | CVar: HUD статистики в углу экрана, даже когда оверлей скрыт |

Полный пример: `samples/guide_examples/29-ui/engine_integration.cpp` (GPU, метка `gpu`). Тест запускает headless-движок, проверяет F1 через `InputSystem`, команды `ui.*` и бенчмарк «Auto».

## Шаг 2. Отладочный оверлей

**F1** или **`~`** показывают оверлей: меню сверху, прозрачная док-область и окна инструментов. Если фокус в текстовом поле, `~` печатается как символ и оверлей не переключает. Пока оверлей открыт, курсор переводится в режим `Normal`, а при закрытии прежний режим возвращается. Раскладка окон сохраняется в `user://imgui.ini`.

| Окно (`DebugTools::k…`) | Что показывает |
| --- | --- |
| **Stats** (`kStats`) | FPS и график времени кадра, CPU игрового потока и потока рендера, GPU по пассам, draw calls, треугольники, видимые и все экземпляры, источники света и карты теней, полоса VRAM |
| **Console** (`kConsole`) | Консоль runtime: лог с фильтрами по уровню и тексту, Tab-дополнение с предпросмотром значения, история по ↑/↓ |
| **Settings & CVars** (`kSettings`) | Уровни Low/Medium/High/Ultra/Auto, уровни по группам, флажок RT (серый, с причиной из `whyRayTracingUnavailable()`), апскейлеры с причинами недоступности, редактирование всех cvar'ов с фильтром |
| **Entity Inspector** (`kInspector`) | Иерархия активного мира, имя и активность сущности, редактирование всех зарегистрированных компонентов через рефлексию: перечисления, цвета, кватернионы как углы Эйлера, массивы, словари, optional |
| **Render Graph** (`kRenderGraph`) | Пассы в порядке выполнения (очередь, батч, барьеры, GPU ms), отброшенные пассы, ресурсы со слотами алиасинга, размерами и временем жизни, память транзиентов, экспорт в Graphviz |
| **Coroutines** (`kCoroutines`) | Список `CoroutineScheduler::coroutines()`, отмена по владельцу (нужен модуль `async`) |
| **Debug Draw** (`kDebugDraw`) | Переключатели отладочной отрисовки физики, ИИ, анимации, звука и сплайнов (нужен `gameplay`), `r.DebugView`, wireframe, отладчик RmlUi, перезагрузка UI |

Правки в окне Settings & CVars идут через консоль, поэтому движок реагирует на них так же, как на набранную команду. Окно Render Graph, пока открыто, ставит `bridge.captureRenderGraph = true`, и рендер каждый кадр снимает скомпилированный план.

Окна работают и без движка (инструменты, тесты): им нужен только контекст.

```cpp
ox::ui::UiConfig cfg;
cfg.gameUI = false;
ox::ui::UiSystem ui(cfg);
ox::Console console;
ox::Settings settings;
ox::ui::DebugTools& tools = ui.enableDebugTools({.console = &console, .settings = &settings});
ui.imgui()->setVisible(true);
tools.open(ox::ui::DebugTools::kConsole);
tools.consoleSubmit("game.Guide.MaxEnemies 32");   // как строка, введённая в окне Console
```

`DebugToolsContext` берёт недостающее из движка: `console`, `services`, `settings` и `world` по умолчанию берутся из `engine`.

Полный пример: `samples/guide_examples/29-ui/imgui_overlay.cpp` (`DebugToolsAndConsole`).

## Шаг 3. Своё отладочное окно

Есть три способа:

| Способ | Когда рисуется | Для чего |
| --- | --- | --- |
| `imgui.addWindow("Меню/Пункт", fn)` | Пока оверлей открыт и окно отмечено в меню **Windows** | Инструменты: спавнер, телепорт, читы |
| `imgui.addAlwaysOnTop(fn)` | Каждый кадр, даже при скрытом оверлее | HUD разработчика (как `ui.ShowStats`) |
| `ImGui::Begin` в коде игры между `beginFrame` и `endFrame` | Всегда, пока код его вызывает | Временная отладка в системе или компоненте |

```cpp
ox::ui::ImGuiLayer& imgui = *ui.imgui();   // ui — сервис UiSystem

int enemies = 3;
const u32 id = imgui.addWindow("Game/Spawner", [&](bool& open) {
    if (ImGui::Begin("Spawner", &open)) {  // крестик окна сбрасывает open → пункт меню снимается
        ImGui::Text("Врагов: %d", enemies);
        if (ImGui::Button("Spawn")) ++enemies;
        ImGui::SliderInt("Count", &enemies, 0, 100);
    }
    ImGui::End();
});

imgui.addAlwaysOnTop([] {
    ImGui::GetForegroundDrawList()->AddText(ImVec2(8, 8), IM_COL32(255, 255, 255, 255), "FPS 60");
});
imgui.addMenu([] {                         // свои пункты в главном меню оверлея
    if (ImGui::BeginMenu("Game")) {
        ImGui::MenuItem("Kill all enemies");
        ImGui::EndMenu();
    }
});

imgui.setWindowOpen("Game/Spawner", true); // открыть программно
imgui.removeWindow(id);                    // убрать при выгрузке
```

Текстуры движка (render targets, ассеты) показываются через bindless-индекс: `ImGui::Image(ImTextureRef(ImGuiLayer::textureId(device.sampledIndex(tex))), size)`. Текстура должна быть в layout `SHADER_READ_ONLY`.

DPI: ImGui работает в логических точках (`framebuffer / dpiScale`). `UiFrame` при этом остаётся в пикселях кадра. На Retina-экране с `dpiScale = 2` кадр 1920×1080 соответствует 960×540 точкам ImGui. Кириллица работает без настройки диапазонов глифов: в ImGui 1.92 шрифты растеризуются по запросу.

Полный пример: `samples/guide_examples/29-ui/imgui_overlay.cpp` (`CustomDebugWindow`, `DirectImGuiCallsDuringTheFrame`, `ToggleKeys`).

## Шаг 4. Игровой UI: документы и стили

Документ `.rml` похож на XHTML, а `.rcss` — на CSS. У RmlUi **нет встроенной таблицы стилей браузера**: `display: block` для `div`/`p`, шрифт и размеры нужно задать самим. В образцах это делает `base.rcss`.

```xml
<!-- ui/scoreboard.rml -->
<rml>
<head>
    <title>Scoreboard</title>
    <link type="text/rcss" href="style.rcss"/>
</head>
<body data-model="score">
    <div id="panel">
        <h1 id="title">#score_title</h1>
        <p id="points">Очки: {{points}}</p>
        <p id="health" data-class-danger="health < 25">Здоровье {{health}}</p>
        <p id="dead" data-if="health <= 0">Вы погибли</p>
        <ul id="enemies">
            <li data-for="e : enemies">{{e}}</li>
        </ul>
        <button id="restart" data-event-click="restart(1)">Заново</button>
        <button id="quit">Выход</button>
    </div>
</body>
</rml>
```

```css
/* ui/style.rcss */
body, div, h1, p, ul, li { display: block; }
body { font-family: Inter; font-size: 16dp; color: #e8ecf2; width: 100%; height: 100%; }
#panel { width: 320dp; padding: 16dp; background-color: #151b26; }
.danger { color: #ff5a4f; }
```

Шрифты по умолчанию: `Inter` (обычный и жирный) и `"JetBrains Mono"`. Оба под лицензией OFL и содержат кириллицу. Единица `dp` масштабируется по DPI.

```cpp
ox::ui::GameUI& game = *ui.gameUI();
Rml::ElementDocument* doc = game.load("scoreboard.rml", /*show*/ true); // root + путь: project://UI/scoreboard.rml
game.show("scoreboard.rml", /*modal*/ false);
game.hide("scoreboard.rml");
game.close("scoreboard.rml");          // выгрузить
game.isVisible("scoreboard.rml");
game.documents();                      // имена загруженных документов
```

Файлы читаются через VFS (`project://`, `user://`, pak). Если путь не находится в VFS, используется путь файловой системы. Документы проекта кладите в `<проект>/UI/`.

**Обработчик по id элемента** переподключается сам после hot reload:

```cpp
u64 id = game.addEventListener("scoreboard.rml", "quit", "click", [](Rml::Event& e) { /* e.GetType() == "click" */ });
game.removeEventListener(id);
```

**Локализация.** `setTranslations({{"score_title", "Счёт"}})` заменяет тексты вида `#score_title`. `setTranslator(fn)` вызывается для каждого текста и атрибута и может вернуть замену или `nullopt`. Оба вызова перезагружают документы.

**Что RmlUi у нас не умеет:** clip masks (обрезку внутри трансформированных элементов), слои, фильтры и шейдерные декораторы. Свойства `filter`, `box-shadow` и градиентные декораторы игнорируются. Трансформированный элемент обрезается только по своему нетрансформированному прямоугольнику.

## Шаг 5. Модели данных (data bindings)

Модель связывает переменные C++ или Lua с документом. **Её нужно создать до загрузки документа**, который ссылается на неё через `data-model="score"`.

```cpp
int points = 120, health = 80;
Rml::String player = "Оксвальд";
std::vector<Rml::String> enemies{"Волк", "Медведь"};

Rml::DataModelConstructor c = game.createModel("score");
c.RegisterArray<std::vector<Rml::String>>();   // массивы и структуры регистрируются один раз на модель
c.Bind("points", &points);
c.Bind("health", &health);
c.Bind("player", &player);
c.Bind("enemies", &enemies);
c.BindEventCallback("restart", [&](Rml::DataModelHandle model, Rml::Event&, const Rml::VariantList& args) {
    restarts += args[0].Get<int>();            // data-event-click="restart(1)"
    points = 0;
    model.DirtyVariable("points");
});

game.load("scoreboard.rml", true);

// C++ изменил данные — сообщите модели, какие поля «грязные». Документ обновится в следующем update().
health = 10;
game.model("score").DirtyVariable("health");
```

| Атрибут в `.rml` | Смысл |
| --- | --- |
| `{{выражение}}` | Текст из переменной или выражения (`{{ musicVolume * 100 \| format(0) }}`) |
| `data-if="health <= 0"` | Элемент существует, только пока условие истинно |
| `data-for="e : enemies"`, `data-for="m, i : modes"` | Повторить элемент для каждого элемента массива (с индексом) |
| `data-class-danger="health < 25"` | Включить класс по условию |
| `data-attr-value="health / maxHealth"`, `data-attrif-disabled="!rtAvailable"` | Значение атрибута; атрибут только при истинном условии |
| `data-value="resolution"`, `data-checked="vsync"` | Двусторонняя привязка полей ввода (`input`, `select`, флажок) |
| `data-event-click="restart(1)"` | Вызвать событие модели с аргументами |

Пользовательские структуры регистрируются через `c.RegisterStruct<T>()` и `RegisterMember`. Так устроена строка апскейлера в модели `settings`. Вычисляемые поля задаются через `c.BindFunc(name, getter, setter)`.

Полный пример: `samples/guide_examples/29-ui/game_ui.cpp` (`DataModelEventsAndTranslations`). Тест проверяет текст, класс `danger`, число элементов `data-for`, событие модели, обработчик по id и перевод `#score_title`.

## Шаг 6. Hot reload

С `GameUIConfig::hotReload = true` (по умолчанию) раз в `hotReloadInterval` секунд проверяются mtime файлов `.rml/.rcss` в каталогах загруженных документов. Если файл изменился, кэши стилей и шаблонов RmlUi сбрасываются и **все** документы перезагружаются. Видимость документов сохраняется, обработчики `addEventListener` подключаются заново, а для каждого документа срабатывает сигнал `documentReloaded`.

```cpp
ox::ScopedConnection c = game.documentReloaded.connect([](const std::string& name) {
    // документ пересоздан: указатели Rml::Element* на его элементы больше недействительны
});
game.pollHotReload(/*force*/ true);   // то же, что консольная команда ui.reload
```

Рабочий цикл художника: запустите игру, откройте `UI/theme.rcss`, поменяйте цвет и сохраните. Изменение появится через полсекунды.

Полный пример: `samples/guide_examples/29-ui/game_ui.cpp` (`HotReloadOfStyleSheet`).

## Шаг 7. Ввод: кто получает щелчок

`UiSystem::processEvent` стоит фильтром в `InputSystem` (`setEventFilter`) и возвращает `true`, если событие поглощено:

1. **ImGui** — клавиши переключения оверлея; нажатия, пока ImGui хочет мышь, клавиатуру или ввод текста (курсор над окном, фокус в поле).
2. **RmlUi** — нажатия над интерактивными элементами, клавиши при фокусе в текстовом поле или когда элемент остановил распространение события.
3. **Игра** — всё остальное.

Движения мыши и отпускания кнопок не поглощаются никогда, поэтому игра не «залипает» с нажатой кнопкой. Чтобы HUD не перехватывал клики по всему экрану, задайте `pointer-events: none` на `body` и `pointer-events: auto` только на кнопках:

```css
body.hud { width: 100%; height: 100%; pointer-events: none; }
.hud-pause { position: absolute; right: 24dp; top: 24dp; pointer-events: auto; }
```

Полный пример: `samples/guide_examples/29-ui/game_ui.cpp` (`InputRoutingAndClickThrough`). В тесте щелчок по кнопке «Пауза» образца `hud.rml` забирает UI, а щелчок по прицелу доходит до игры.

## Шаг 8. Меню настроек графики (модель `settings`)

`UiSystem::attach` вызывает `GameUI::bindSettingsMenu(engine.settings(), hooks)`. Документу достаточно `data-model="settings"`. Образец `settings.rml` — готовое меню. Каждое изменение идёт через `Settings::setGraphics/setAudio`: cvar'ы, уровни масштабируемости, сигнал `changed`, после чего окно и рендерер применяют настройки. Подробно о `Settings` — в [главе 04](04-cvars-quality.md).

| Переменная | Тип | Смысл |
| --- | --- | --- |
| `qualities`, `quality` | массив строк, строка | `Low/Medium/High/Ultra/Auto` и текущий уровень |
| `autoStatus` | строка | Итог бенчмарка («Auto: High (score …)») |
| `windowModes`, `windowMode` | массив, индекс | Оконный, без рамки, полноэкранный |
| `resolutions`, `resolution` | массив, строка | `"Native"` + режимы мониторов GLFW (ширина ≥ 1024). Без окна — 1280×720 … 3840×2160 |
| `vsync`, `rayTracing` | bool | Двусторонние привязки |
| `rtAvailable`, `rtReason` | bool, строка | Доступность RT по `DeviceCaps` |
| `upscalers[]` | `{name, available, reason}` | `Off`, `FSR1`, `DLSS` |
| `upscaler`, `upscalerReason` | строка | Текущий апскейлер; причины недоступности остальных |
| `masterVolume`, `musicVolume`, `sfxVolume` | float 0..1 | Общая громкость и шины `Music`, `SFX` |
| `status` | строка | Последнее сообщение («Settings saved», «Ray tracing unavailable: …») |

| Событие | Действие |
| --- | --- |
| `set_quality(q)` | Уровень качества. `'Auto'` запускает GPU-бенчмарк между кадрами рендера, результат применяется на игровом потоке и приходит сигналом `UiSystem::qualityAutoDetected` |
| `set_upscaler(n)` | Апскейлер (недоступный не выбирается, в `status` пишется причина) |
| `set_window_mode(i)`, `toggle_vsync`, `toggle_rt` | Окно, VSync, трассировка лучей |
| `save`, `revert` | Записать `user://settings.json` / перечитать и применить |

```xml
<button class="choice quality" data-for="q : qualities" data-attr-id="'quality-' + q"
        data-class-selected="q == quality" data-event-click="set_quality(q)">{{q}}</button>
<input id="raytracing" type="checkbox" data-checked="rayTracing" data-attrif-disabled="!rtAvailable"/>
<button class="choice upscaler" data-for="u : upscalers" data-class-unavailable="!u.available"
        data-attr-title="u.reason" data-event-click="set_upscaler(u.name)">{{u.name}}</button>
```

Доступность берётся из `DeviceCaps` рендерера (`ui::upscalerAvailability(caps)`). FSR1 доступен везде. DLSS — только на NVIDIA RTX под Windows/Linux, на macOS он всегда серый с причиной. Без движка или в тестах хуки задаются вручную:

```cpp
ox::ui::SettingsMenuHooks hooks;
hooks.requestAutoDetect = [&] { /* запустить бенчмарк */ };
hooks.rayTracingAvailable = [](std::string& reason) { reason = "MoltenVK не поддерживает Vulkan ray tracing"; return false; };
hooks.upscalers = [] {
    return std::vector<ox::ui::UpscalerAvailability>{{"Off", true, {}}, {"FSR1", true, {}}, {"DLSS", false, "нужна NVIDIA RTX"}};
};
game.bindSettingsMenu(settings, hooks);
game.load("settings.rml", true);
```

| Поле `SettingsMenuHooks` | По умолчанию |
| --- | --- |
| `requestAutoDetect` | Нет: «Auto» только отмечается |
| `rayTracingAvailable` | RT недоступен |
| `upscalers` | Только FSR1 (и `Off`) |
| `resolutions` | Распространённые 16:9 |
| `saveOnChange` | `false`: сохранение по кнопке `save` |

Полный пример: `samples/guide_examples/29-ui/game_ui.cpp` (`SettingsMenuChangesQuality`). Тест нажимает Low, Auto, DLSS (серый) и FSR1 и проверяет `scalability::overallLevel()` и `settings.user().graphics`.

## Шаг 9. Образцы меню

В `engine/ui/resources/sample/` лежит готовый набор. Скопируйте его в `<проект>/UI/`:

| Файл | Что внутри |
| --- | --- |
| `base.rcss` | Замена таблицы стилей браузера: `display`, шрифты, заголовки, поля ввода, таблицы |
| `theme.rcss` | Тёмные «стеклянные» панели с синим акцентом, кнопки с переходами, флажки, слайдеры, `select`, стили HUD |
| `main_menu.rml` | Главное меню: кнопки `play`, `continue`, `settings`, `quit` |
| `hud.rml` | HUD над моделью `hud` (`health`, `maxHealth`, `ammo`, `reserve`, `objective`): полоса здоровья (класс `low` ниже 25 %), патроны, цель, прицел, кнопка `pause` |
| `settings.rml` | Меню настроек над моделью `settings` (шаг 8), кнопка `back` |
| `menu.lua` | Связка «меню → настройки → HUD» на Lua-API `ui` и Lua-окно отладки HUD |

`menu.lua` вешается на сущность как скрипт (или запускается из стартового скрипта). Он создаёт модель `hud`, загружает три документа, по `play` прячет меню, показывает HUD и захватывает курсор (`input.setCursorMode("Locked")`), а по Esc возвращает меню.

Полный пример: `samples/guide_examples/29-ui/game_ui.cpp` (`SampleDocumentsLoad`) — все образцы загружаются без ошибок RmlUi.

## Шаг 10. UI из Lua

Если при сборке ui есть модуль `script`, `UiSystem::attach` регистрирует в `ScriptVM` две таблицы: `ui` (игровой UI) и `debug` (ImGui в немедленном режиме).

```lua
-- scripts/quest_ui.lua
local quest

function onCreate(self)
    self.accepted = 0
    -- Модель создаётся ДО загрузки документа с data-model="quest".
    quest = ui.createModel("quest", { title = "Волки у мельницы", reward = 50 }, {
        accept = function(args) self.accepted = self.accepted + args[1] end,   -- data-event-click="accept(reward)"
    })
    ui.load("quest.rml", true)
    ui.on("quest.rml", "close", "click", function(ev)   -- ev.type, ev.target, ev.value, ev.x, ev.y
        ui.hide("quest.rml")
    end)
end

function onUpdate(self, dt)
    debug.window("Quest debug", function()
        local reward, changed = debug.sliderFloat("reward", quest:get("reward"), 0, 500)
        if changed then quest:set("reward", math.floor(reward)) end
        if debug.button("Double reward") then quest:set("reward", quest:get("reward") * 2) end
    end)
end
```

**Таблица `ui`:**

| Функция | Что делает |
| --- | --- |
| `ui.load(path [, show])` → bool | Загрузить документ |
| `ui.show(name [, modal])`, `ui.hide(name)`, `ui.close(name)`, `ui.isVisible(name)` | Видимость и выгрузка |
| `ui.on(doc, id, event, fn)` → id; `ui.off(id)` | Обработчик события элемента; `fn(ev)` получает `type`, `target`, `value`, `x`, `y` |
| `ui.createModel(name, fields, events)` → model | Модель данных: поля (числа, строки, bool) и события `fn(args)` |
| `ui.model(name)` | Найти модель, созданную из Lua |
| `model:set(key, value)`, `model:get(key)`, `model:on(event, fn)` | Поле модели (`set` помечает его «грязным»), новое событие |
| `ui.setText(doc, id, rml)`, `ui.getText(doc, id)`, `ui.setClass(doc, id, class, on)` | Прямая работа с элементами |
| `ui.setTranslations({ key = "текст" })` | Таблица перевода для `#key` |
| `ui.debugOverlayVisible()` | Открыт ли оверлей |

**Таблица `debug`** (подмножество ImGui):

| Функция | Возвращает |
| --- | --- |
| `debug.window(title, fn)` | Видимо ли окно; `fn` вызывается внутри `Begin/End` |
| `debug.beginWindow(title)` / `debug.endWindow()` | Ручной вариант; незакрытые окна закрываются в конце кадра |
| `debug.text(...)` | Аргументы через пробел |
| `debug.button(label)` | `true` в кадр нажатия |
| `debug.checkbox(label, v)`, `debug.sliderFloat(label, v [, min, max])`, `debug.inputText(label, s)`, `debug.colorEdit(label, c)` | Новое значение и `changed`. Слайдер по умолчанию 0..1; цвет — `vec3`, `vec4` или `{r, g, b, a}` |
| `debug.plotLines(label, values [, overlay, min, max, height])` | График, высота по умолчанию 60 |
| `debug.separator()`, `debug.sameLine()`, `debug.overlayVisible()` | Разметка и состояние оверлея |

Вызовы `debug.*` вне кадра UI ничего не делают и не дают ошибок. Окно ImGui существует, пока скрипт вызывает `debug.window` каждый кадр (обычно в `onUpdate`). Новое окно с авторазмером невидимо в свой первый кадр.

`ScriptVM` должна жить дольше привязок. В движке это обеспечено: сервис `UiSystem` уничтожается раньше `ScriptVM`. В своих инструментах вызывайте `ui.unbindLua()` до уничтожения VM.

Полный пример: `samples/guide_examples/29-ui/lua_ui.cpp` + `scripts/quest_ui.lua` + `ui/quest.rml`.

## Шаг 11. Как UI рисуется

`UiOverlayFeature` (`kName = "UI"`) — один графический пасс после `EditorOverlays`/`DebugLines`, `color(SceneColorLDR, LOAD)` в выходном разрешении (после апскейла и тонмаппинга). Вершины и индексы читаются по buffer device address, текстуры — bindless с сэмплером `LinearClamp`, для каждой команды задаётся свой scissor, смешивание премультиплицированное. `SceneColorLDR` уже в дисплейном кодировании, поэтому цвета UI, заданные в sRGB, пишутся как есть.

| Что | Значение |
| --- | --- |
| Стоимость пасса UI | ≈ 0.11–0.34 мс GPU (Apple M4 Pro, 1080p, 4 отладочных окна, в том числе консоль на 200 строк, + меню настроек RmlUi: 71 draw, 8.1 K вершин) |
| Задержка | ≤ 1 кадр («последний кадр побеждает») |
| Редакторские вьюпорты | Не рисуется, пока не включено `bridge.drawInEditorViews` |
| Виды с `ViewFlags::overlays == false` | Пропускаются |
| Загрузка текстур | Синхронно на потоке рендера при изменении (рост атласа шрифта — несколько кадров на старте) |

Для своих инструментов без движка рендерер подключается вручную: `ox::ui::attachRenderer(renderer, ui.bridgeShared())`.

## Типичные ошибки и подводные камни

- **Модель создана после `load`.** Документ с `data-model="hud"` уже разобран без модели, и `{{health}}` не работает. Создавайте модель (`createModel` / `ui.createModel`) до загрузки документа.
- **Значение поменялось, а текст — нет.** После изменения переменной из C++ вызовите `game.model("x").DirtyVariable("field")`. В Lua `model:set` делает это сам.
- **Пустая страница или «слипшийся» текст.** У RmlUi нет таблицы стилей браузера: без `display: block` и `font-family` всё строчное и без шрифта. Подключайте `base.rcss` из образцов.
- **HUD съедает клики.** На `body` HUD нужен `pointer-events: none`, а на кнопках — `pointer-events: auto`.
- **Указатели `Rml::Element*` после hot reload.** Документ пересоздан, старые указатели недействительны. Ищите элементы заново (`document(name)->GetElementById`) или используйте `addEventListener`, который переподключается сам.
- **Два `GameUI` одновременно.** У RmlUi глобальное состояние: в процессе допускается один `GameUI` и один контекст.
- **Окно ImGui «мигает» или не видно в первом кадре.** Новое окно с авторазмером скрыто в свой первый кадр. Вызывайте его каждый кадр, а не один раз.
- **ImGui-вызовы вне кадра.** `ImGui::*` безопасны только между `beginFrame` и `endFrame` (в движке — между `preUpdate` и концом кадра). Lua `debug.*` вне кадра просто ничего не делает.
- **Пользовательские draw callbacks ImGui** пропускаются: они выполнялись бы на игровом потоке. Мульти-вьюпорты ImGui не поддерживаются.
- **`~` не открывает оверлей.** Фокус в текстовом поле: символ печатается. Используйте F1.
- **DLSS в меню всегда серый на Mac.** Это ожидаемо: NGX есть только на Windows/Linux с NVIDIA RTX. Причина видна в подсказке (`title`) и в `upscalerReason`.
- **ScriptVM уничтожена раньше UiSystem** (в своих инструментах) — падение при уничтожении Lua-обработчиков. Вызовите `ui.unbindLua()` первым.
