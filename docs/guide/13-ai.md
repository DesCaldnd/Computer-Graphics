# 13. Искусственный интеллект

> Модуль `ai` (таргет `Oxwald::ai`, пространство имён `ox::ai`). Навигация построена на Recast/Detour (DetourCrowd, DetourTileCache 1.6); также в модуле есть деревья поведения, blackboard, utility AI и система восприятия. Модуль зависит только от `core`, glm и nlohmann-json, не знает ни про ECS, ни про физику. Компоненты «ИИ-агент» и «навмеш» на сцене описаны в главе о геймплейных компонентах ECS (*скоро*).

## Зачем

Типичному NPC нужно четыре вещи, и модуль даёт каждую отдельным, независимо используемым блоком:

1. **Куда можно идти** — навигационный меш (navmesh). Он строится из геометрии уровня с учётом размеров агента. По нему ищется путь, на нём отмечаются зоны (вода, дорога, двери) и прыжки.
2. **Как идти в толпе** — `NavCrowd`: локальное рулевое управление (steering), расталкивание, обход других агентов. Для подвижных препятствий есть `NavTileCache`, который быстро «вырезает» ящики и бочки из навмеша.
3. **Что решать** — деревья поведения (behavior trees) с общим blackboard и наблюдателями в стиле Unreal, загрузка деревьев из JSON. Для «мягкого» выбора между вариантами есть utility AI.
4. **Что NPC знает о мире** — `PerceptionSystem`: зрение (конус, периферия, линия видимости), слух (шумы), память о последней известной позиции, команды и отношения между ними.

Вся система работает на CPU, детерминирована (случайные запросы принимают seed) и проверяется обычными юнит-тестами без движка и рендера.

## Ключевые понятия

| Понятие | Что это |
| --- | --- |
| `NavMeshInput` | «Суп» треугольников уровня + зоны по треугольникам, off-mesh связи, выпуклые объёмы зон |
| `NavMeshBuildSettings` | Размер вокселя, параметры агента (радиус, рост, подъём, уклон), тайлы |
| `NavMesh` | Готовый навмеш Detour: цельный (solo) или тайловый; сериализация, флаги полигонов |
| `NavArea` / `NavFlags` | Зона полигона (Ground, Water, Road, Door, Grass, Jump) и флаги способностей (Walk, Swim, Door, Jump, Disabled) |
| `NavQueryFilter` | Стоимость прохода по зонам + маски включения и исключения флагов: «кто как ходит» |
| `NavQuery` | Запросы: путь, ближайшая точка, луч по навмешу, случайная точка, высота |
| `NavCrowd` / `NavAgent` | Толпа агентов с локальным избеганием столкновений |
| `NavTileCache` | Навмеш с динамическими препятствиями (цилиндр, бокс, повёрнутый бокс) |
| `Blackboard` | Типизированное хранилище «ключ → значение» с наблюдателями |
| `BehaviorTree`, `BTBuilder`, `BTFactory` | Дерево поведения, его построитель в коде и загрузчик из JSON |
| `PerceptionSystem` | Зрение, слух и память слушателей (listeners) о источниках (sources) |
| `UtilityScorer` | Выбор действия по произведению оценок (considerations) с кривыми отклика |

## Шаг 1. Навмеш из геометрии

Навмеш строится из треугольников. Обычно это статические коллизионные меши уровня, но в примерах геометрия собирается прямо в коде. Хелперы `addQuad`/`addBox` создают треугольники с правильным порядком обхода: **против часовой стрелки при взгляде сверху** означает, что проходимая сторона смотрит вверх.

```cpp
#include <oxwald/ai/nav_query.hpp>
#include <oxwald/ai/navmesh.hpp>
using namespace ox::ai;

NavMeshInput in;
in.addQuad({-10, 0, -10}, {-10, 0, 10}, {10, 0, 10}, {10, 0, -10}); // пол 20 × 20 м
in.addBox({-0.5f, 0.f, -6.f}, {0.5f, 3.f, 10.f});                   // стена с проходом при z < −6

NavMeshBuildSettings s;
s.cellSize = 0.2f;     // точность вокселизации по XZ
s.cellHeight = 0.1f;   // и по Y
s.agentRadius = 0.4f;
s.agentHeight = 1.8f;
s.agentMaxClimb = 0.5f;
s.agentMaxSlope = 45.f;
std::unique_ptr<NavMesh> mesh = NavMesh::build(in, s);   // nullptr (+ лог) при ошибке
mesh->stats();   // tiles, polygons, vertices, offMeshLinks, dataBytes
```

Для своего меша заполните `in.vertices` (`glm::vec3`) и `in.indices` (по три `uint32_t` на треугольник), а при желании и `in.triAreas` (одна зона на треугольник, по умолчанию `Ground`). Несколько источников объединяются через `in.append(other)`.

Основные настройки сборки:

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `cellSize` / `cellHeight` | 0.3 / 0.2 м | Размер вокселя. Меньше — точнее и медленнее. Хорошее правило: `cellSize ≈ agentRadius / 2` |
| `agentRadius` | 0.5 м | Отступ от стен: навмеш «сжимается» на радиус агента |
| `agentHeight` | 2.0 м | Минимальный просвет над полом |
| `agentMaxClimb` | 0.9 м | Высота ступеньки, на которую можно шагнуть |
| `agentMaxSlope` | 45° | Максимальный уклон |
| `regionMinSize` / `regionMergeSize` | 8 / 20 | Удаление мелких островков и слияние регионов (в клетках) |
| `edgeMaxLen` / `edgeMaxError` | 12 м / 1.3 | Упрощение контуров |
| `vertsPerPoly` | 6 | Максимум вершин в полигоне |
| `detailSampleDist` / `detailSampleMaxError` | 6 / 1 | Детализация по высоте (`< 0.9` отключает) |
| `partition` | `Watershed` | Разбиение на регионы: `Watershed`, `Monotone` (быстрее), `Layers` |
| `tiled` / `tileSize` | `false` / 48 | Тайловый навмеш и размер тайла в клетках |
| `areaFlags` | `defaultAreaFlags()` | Таблица «зона → флаги» |

## Шаг 2. Поиск пути и запросы

```cpp
NavQuery query(*mesh);   // не потокобезопасен: по объекту на поток / систему
const NavPath path = query.findPath({-5, 0, 5}, {5, 0, 5});
switch (path.status) {
case PathStatus::Complete: break;  // путь до цели
case PathStatus::Partial:  break;  // цель недостижима: путь до ближайшей достижимой точки
case PathStatus::Failed:   break;  // старт или цель не на навмеше
}
path.points;      // «натянутый» путь (string pulling): углы, которые нужно обойти
path.pointFlags;  // биты PathPointFlag: Start, End, OffMeshLink
path.corridor;    // коридор полигонов
path.length();

// Плотный путь по поверхности (точки через ~0.5 м) — удобно вести персонажа по высоте рельефа.
std::vector<glm::vec3> smooth = query.smoothPath({-5, 0, 5}, {5, 0, 5}, {}, 0.5f);
```

Другие запросы:

```cpp
std::optional<NavPoint> n = query.nearestPoint({3.f, 1.f, 3.f});  // «приземлить» точку спавна
NavRaycastHit hit = query.raycast({-5, 0, 5}, {5, 0, 5});          // упрёмся ли в стену по навмешу
auto a = query.randomPointInRadius({-5, 0, 5}, 3.f, /*seed*/ 42);  // точка патруля; один seed — один результат
std::optional<float> y = query.heightAt({3, 0.5f, 3});
query.setSearchExtents({2, 4, 2});  // полуразмеры коробки поиска при «прилипании» точек к навмешу
```

Полный пример: `samples/guide_examples/13-ai/navmesh.cpp`.

## Шаг 3. Зоны, флаги и фильтры

Зона (area) определяет **стоимость** прохода, а флаги определяют, **может ли** агент вообще пройти. Флаги получаются из зоны по таблице `areaFlags`: Ground/Road/Grass → `Walk`, Water → `Swim`, Door → `Walk | Door`, Jump → `Jump`.

Зону можно задать для треугольников (`triAreas`) или объёмом: всё, что внутри вертикальной призмы, получает её зону.

```cpp
in.volumes.push_back({.points = {{-1, 0, -11}, {-1, 0, 11}, {1, 0, 11}, {1, 0, -11}},  // контур по XZ
                      .minY = -1.f, .maxY = 1.f, .area = NavArea::Water});
auto mesh = NavMesh::build(in, s);

// Фильтр по умолчанию: вода дорогая (стоимость 10), но проходимая.
query.findPath(a, b);

// Агент, который не умеет плавать.
NavQueryFilter landOnly;
landOnly.excludeFlags |= NavFlags::Swim;
query.findPath(a, b, landOnly);   // Partial: дойдёт до берега
```

Стоимости по умолчанию в `NavQueryFilter::areaCost`: всё 1, Water 10, Road 0.8, Grass 1.5, Jump 1.5. Фильтр по умолчанию исключает флаг `Disabled`.

**Off-mesh связи** (off-mesh links) соединяют несвязанные участки: прыжок через пропасть, лестница, телепорт.

```cpp
in.offMeshLinks.push_back({.start = {-1.6f, 0, 0}, .end = {1.6f, 0, 0}, .radius = 0.5f, .area = NavArea::Jump});
// ...
for (size_t i = 0; i < path.points.size(); ++i)
    if (path.pointFlags[i] & static_cast<uint8_t>(PathPointFlag::OffMeshLink))
        { /* здесь проиграть анимацию прыжка */ }
```

Флаги полигонов можно менять **во время игры**, например «закрыть дверь»:

```cpp
const auto doorway = query.nearestPoint(doorPosition);
mesh->setPolyFlags(doorway->poly, NavFlags::Disabled);  // путь через проход исчез
mesh->setPolyFlags(doorway->poly, NavFlags::Walk);      // открыли
```

**Сериализация.** Навмеш запекают в редакторе или инструменте и грузят в игре без пересборки:

```cpp
std::vector<uint8_t> blob = mesh->serialize();
std::unique_ptr<NavMesh> loaded = NavMesh::deserialize(blob);   // nullptr на мусорных данных
```

Полный пример: `samples/guide_examples/13-ai/navmesh.cpp` (`AreasFlagsAndFilters`, `OffMeshLinkJumpsAGap`, `SerializeAndCloseADoorAtRuntime`).

## Шаг 4. Толпа

`NavCrowd` ведёт агентов по навмешу: ищет путь, сглаживает углы, расталкивает агентов и избегает столкновений. Вы ставите цель и каждый фиксированный шаг читаете позицию.

```cpp
#include <oxwald/ai/nav_crowd.hpp>

NavCrowd crowd(*mesh, /*maxAgents*/ 32, /*maxAgentRadius*/ 1.f);
NavAgentParams params;
params.radius = 0.4f;
params.maxSpeed = 3.f;
params.obstacleAvoidanceQuality = 3;     // 0..3: выше — аккуратнее и дороже

NavAgent agent = crowd.addAgent({-6, 0, 0}, params);
crowd.setTarget(agent, {6, 0, 0});       // false, если цель далеко от навмеша

// Фиксированный шаг симуляции:
crowd.update(1.f / 20.f);
glm::vec3 p = crowd.position(agent);     // → трансформ сущности
glm::vec3 v = crowd.velocity(agent);     // → скорость для blend space анимации
if (crowd.reachedTarget(agent, 0.6f)) { /* пришли */ }
```

| Поле `NavAgentParams` | По умолчанию | Смысл |
| --- | --- | --- |
| `radius`, `height` | 0.5, 2 | Размер агента (радиус не больше `maxAgentRadius` толпы) |
| `maxSpeed`, `maxAcceleration` | 3.5, 8 | Динамика |
| `collisionQueryRange` | 0 → radius × 12 | Радиус поиска соседей |
| `pathOptimizationRange` | 0 → radius × 30 | Дальность оптимизации пути по видимости |
| `separationWeight` | 2 | Сила расталкивания |
| `obstacleAvoidanceQuality` | 3 | Качество избегания (0..3) |
| `anticipateTurns`, `optimizeVisibility`, `optimizeTopology`, `separation`, `obstacleAvoidance` | `true` | Флаги поведения DetourCrowd |
| `filterIndex` | 0 | Индекс фильтра (`crowd.setFilter(i, filter)`) — «пловцы» и «сухопутные» в одной толпе |

Ещё есть `setVelocity` (прямое управление без пути, например для игрока под управлением ИИ), `resetTarget`, `removeAgent`, `state` (`Walking`/`OffMeshLink`) и `debugDraw`.

Полный пример: `samples/guide_examples/13-ai/crowd_obstacles.cpp` (`GuideAiCrowd`). Восемь агентов идут навстречу друг другу и расходятся.

## Шаг 5. Меняющийся мир: тайлы и динамические препятствия

Есть два способа обновить навмеш во время игры.

**Тайловая пересборка.** Подходит для больших изменений геометрии: построили стену, разрушили мост. Навмеш строится тайлами, а пересобираются только тайлы, задетые изменением.

```cpp
NavMeshBuildSettings s = agentSettings;
s.tiled = true;
s.tileSize = 32;                 // клеток на сторону (32 × 0.2 = 6.4 м)
auto mesh = NavMesh::build(level, s);

NavMeshInput withWall = level;
withWall.addBox(wmin, wmax);
int rebuilt = mesh->rebuildTiles(withWall, wmin, wmax);  // только тайлы под AABB изменения
```

`NavQuery`, созданный раньше, продолжает работать с обновлённым мешем: пересоздавать его не нужно.

**Tile cache.** Подходит для частых мелких препятствий: ящики, бочки, машины, баррикады. Изменение обрабатывается дешевле, его можно делать хоть каждый кадр.

```cpp
#include <oxwald/ai/nav_tile_cache.hpp>

NavTileCacheSettings s;
s.build = agentSettings;
s.build.tileSize = 32;
s.maxObstacles = 64;
std::unique_ptr<NavTileCache> cache = NavTileCache::build(level, s);
NavQuery query(cache->navMesh());          // запросы и толпа — как с обычным навмешем

NavObstacleId barricade = cache->addBox({-0.5f, -0.5f, -7.f}, {0.5f, 2.f, 7.f});
NavObstacleId barrel = cache->addCylinder({-5.f, -0.5f, 3.f}, /*radius*/ 1.f, /*height*/ 2.f);
// cache->addOrientedBox(center, halfExtents, yawRadians);
cache->update(dt);   // каждый кадр: обрабатывает очередь, true — навмеш актуален
cache->flush();      // или всё сразу (загрузка уровня, тесты)
cache->removeObstacle(barricade);
```

Полный пример: `samples/guide_examples/13-ai/crowd_obstacles.cpp` (`GuideAiTiles`, `GuideAiTileCache`).

## Шаг 6. Blackboard

Blackboard — общая «память» дерева поведения и игрового кода. Поддерживаемые типы: `bool`, `int32_t`, `float`, `std::string`, `glm::vec3`, `uint64_t` (id сущностей).

```cpp
#include <oxwald/ai/blackboard.hpp>

Blackboard bb;
bb.set("health", 100);               // знаковые целые → i32
bb.set("speed", 2.5f);               // → f32
bb.set("state", "patrol");           // → std::string
bb.set("home", glm::vec3(1, 0, 3));
bb.set("target", uint64_t{42});      // беззнаковые → u64

bb.get<int32_t>("health");           // std::optional; при несовпадении типа — nullopt
bb.getOr<int32_t>("ammo", 0);
bb.has("target"); bb.erase("target");

auto id = bb.observe("health", [](const std::string& key, const BlackboardValue& oldV, const BlackboardValue& newV) {
    // синхронно, только при реальном изменении значения; ключ "" — все ключи
});
bb.unobserve(id);
bb.version();                        // растёт при каждом изменении — дешёвая проверка «что-то поменялось»

nlohmann::json j;
bb.saveJson(j); bb.loadJson(j);      // сохранения, отладочные дампы
```

Полный пример: `samples/guide_examples/13-ai/behavior_tree.cpp` (`GuideAiBlackboard`).

## Шаг 7. Деревья поведения

Узел возвращает `Running`, `Success` или `Failure` (`Idle` значит, что узел ещё не тикал). Дерево тикается раз в кадр (или реже) с `dt`.

| Узел | Тип | Поведение |
| --- | --- | --- |
| `Sequence` | composite | Дети по порядку; провал на первом провале |
| `Selector` | composite | Дети по приоритету; успех на первом успехе; поддерживает прерывания `LowerPriority` |
| `Parallel` | composite | Все дети каждый тик; политики успеха/провала `RequireOne`/`RequireAll` |
| `Inverter`, `Succeeder` | decorator | Инверсия / всегда успех |
| `Repeater(count, ignoreFailure)` | decorator | Повтор (`-1` — бесконечно), одно завершение ребёнка за тик |
| `Cooldown(s)` | decorator | После завершения ребёнка `s` секунд сразу возвращает провал |
| `Timeout(s)` | decorator | Прерывает ребёнка и проваливается, если он работает дольше `s` |
| `BlackboardCondition` | decorator / leaf | Проверка ключа (`IsSet`, `Equals`, `Less`, …) + наблюдатель (abort) |
| `Condition`, `Action` | leaf | Лямбды; у `Action` есть необязательный `onAbort` |
| `Wait(s)`, `SetBlackboard(key, value)` | leaf | Ожидание; запись в blackboard |
| `SubTree` | decorator | Экземпляр другого (зарегистрированного) дерева |

Дерево охранника: патрулирует, а заметив цель, прерывает патруль и стреляет.

```cpp
#include <oxwald/ai/behavior_tree.hpp>

auto blackboard = std::make_shared<Blackboard>();
auto tree = BTBuilder()
    .selector("Root")
        // Появилась цель — прервать патруль (LowerPriority); пропала — прервать бой (Self).
        .blackboardCondition("target", BBOp::IsSet, {}, BTAbortMode::Both, "HasTarget")
            .sequence("Combat")
                .action("Shoot", [](BTContext& ctx) {
                    static_cast<Guard*>(ctx.user)->shots++;
                    return BTStatus::Success;
                })
                .wait(0.5f)
            .end()
        .sequence("Patrol")
            .action("MoveToWaypoint",
                    [](BTContext& ctx) {
                        auto* g = static_cast<Guard*>(ctx.user);
                        g->moving = ++g->patrolSteps % 3 != 0;
                        return g->moving ? BTStatus::Running : BTStatus::Success;
                    },
                    [](BTContext& ctx) { static_cast<Guard*>(ctx.user)->moving = false; })  // onAbort
            .wait(0.2f)
        .end()
    .end()
    .build(blackboard);
tree->setUserData(&guard);       // в узлах — ctx.user

tree->tick(dt);
blackboard->set("target", uint64_t{7});   // восприятие заметило игрока
tree->tick(dt);                            // патруль прерван (onAbort), начался бой
blackboard->erase("target");
tree->tick(dt);                            // снова патруль
```

Правила построителя: декоратор оборачивает **ровно следующий** узел, композит закрывается `end()`. Свой узел добавляется через `.node(std::make_unique<MyNode>(...))`.

**Прерывания по наблюдателю** (observer aborts) работают как в Unreal:

| `BTAbortMode` | Когда срабатывает |
| --- | --- |
| `None` | Условие проверяется, только когда до него дошёл тик |
| `Self` | Ветка под условием работает, ключ изменился, условие стало ложным: ветка прерывается |
| `LowerPriority` | Работает более поздний ребёнок родительского `Selector`, условие стало истинным: он прерывается, управление переходит сюда |
| `Both` | Оба варианта |

Условия переоцениваются только при изменении отслеживаемого ключа, так что это дёшево.

**Отладка.** `tree->trace()` возвращает для каждого узла `{id, parentId, depth, name, type, status, lastTick, tickedThisFrame}`: этого хватает для визуализатора дерева. `setTraceCallback` позволяет логировать тики, а `findNode("Combat")->running()` — проверять узлы в тестах.

Полный пример: `samples/guide_examples/13-ai/behavior_tree.cpp` (`GuardPatrolsAndSwitchesToCombat`).

### Деревья в JSON

Дизайнеры могут править деревья как данные. Действия и условия регистрируются в коде по имени, а структура лежит в JSON (`samples/guide_examples/13-ai/guard.bt.json`):

```json
{
  "blackboard": { "alert": false, "ammo": 3 },
  "root": {
    "type": "Selector", "name": "Root",
    "children": [
      { "type": "BlackboardCondition", "name": "HasTarget", "key": "target", "op": "IsSet", "abort": "Both",
        "child": { "type": "Sequence", "name": "Combat", "children": [
          { "type": "BlackboardCondition", "key": "ammo", "op": "Greater", "value": 0 },
          { "type": "Action", "action": "Shoot" },
          { "type": "Wait", "seconds": 0.2 }
        ] } },
      { "type": "Repeater", "count": -1, "child": { "type": "SubTree", "tree": "Patrol" } }
    ]
  }
}
```

```cpp
BTFactory factory;   // встроенные узлы уже зарегистрированы
factory.registerAction("Shoot", [&](BTContext& ctx) {
    ctx.blackboard.set("ammo", ctx.blackboard.getOr<int32_t>("ammo", 0) - 1);
    return BTStatus::Success;
});
factory.registerAction("MoveToWaypoint", moveFn /*, onAbort */);
factory.registerCondition("IsAngry", [](BTContext& ctx) { return ctx.blackboard.getOr<bool>("angry", false); });
factory.registerTree("Patrol", nlohmann::json::parse(R"({
    "type": "Sequence", "children": [
        { "type": "Action", "action": "MoveToWaypoint" },
        { "type": "Wait", "seconds": 1.0 } ] })"));

std::unique_ptr<BehaviorTree> tree = factory.loadFile("ai/guard.bt.json");  // или factory.load(json)
// Ошибки (неизвестный тип, незарегистрированное действие) логируются, результат — nullptr.

nlohmann::json saved = tree->toJson();        // обратно в JSON (редактор)
BTFactory::saveFile(*tree->root(), "out.json");
```

Формат: у узла есть `type`, `name`, у композитов — `children`, у декораторов — `child`, остальные параметры плоские (`seconds`, `key`, `op`, `value`, `abort`, `action`, `condition`, `tree`, `count`, `success`/`failure`). Значения переводятся так: bool/int/float/string → соответствующий тип, `[x, y, z]` → `vec3`, `{"id": n}` → `u64`. Операции: `IsSet`, `IsNotSet`, `Equals`, `NotEquals`, `Less`, `LessOrEqual`, `Greater`, `GreaterOrEqual` (числа сравниваются численно, `int` с `float` тоже).

Свой тип узла регистрируется фабрикой:

```cpp
class IsNear final : public BTNode {
public:
    IsNear(std::string key, float radius) : BTNode("IsNear"), m_key(std::move(key)), m_radius(radius) {}
    const char* typeName() const override { return "IsNear"; }
    void saveParams(nlohmann::json& j) const override { j["key"] = m_key; j["radius"] = m_radius; }
protected:
    BTStatus onTick(BTContext& ctx) override {
        const glm::vec3 self = ctx.blackboard.getOr<glm::vec3>("position", glm::vec3(0.f));
        const auto goal = ctx.blackboard.get<glm::vec3>(m_key);
        return goal && glm::distance(self, *goal) < m_radius ? BTStatus::Success : BTStatus::Failure;
    }
private:
    std::string m_key;
    float m_radius;
};

factory.registerNode("IsNear", [](const nlohmann::json& j, const BTFactory&) {
    return std::make_unique<IsNear>(j.value("key", std::string("goal")), j.value("radius", 1.f));
});
```

Кроме `onTick` можно переопределить `onEnter`, `onExit(ctx, result)` и `onAbort`. Для своих композитов и декораторов наследуйтесь от `BTComposite`/`BTDecorator`.

Полный пример: `samples/guide_examples/13-ai/behavior_tree.cpp` (`LoadFromJsonFile`, `CustomNodeInBuilderAndFactory`).

## Шаг 8. Utility AI

Когда вариантов много и решение «мягкое» (лечиться, атаковать, искать укрытие), удобнее считать полезность. Каждое действие — это произведение оценок (considerations): вход 0..1 из blackboard проходит через кривую отклика (`ResponseCurve`) и даёт 0..1. Компенсационный множитель не даёт штрафовать действия, у которых оценок много.

```cpp
#include <oxwald/ai/utility_ai.hpp>

UtilityScorer brain;
brain.addAction({.name = "Heal",
                 .considerations = {{.name = "LowHealth",
                                     .input = [](const Blackboard& bb) { return 1.f - bb.getOr<float>("health", 1.f); },
                                     .curve = {.type = ResponseCurve::Type::Polynomial, .exponent = 2.f}}}});
brain.addAction({.name = "Attack",
                 .considerations = {{.name = "Healthy", .input = [](const Blackboard& bb) { return bb.getOr<float>("health", 1.f); }},
                                    {.name = "EnemyNear", .input = [](const Blackboard& bb) { return bb.getOr<float>("enemy", 0.f); }}}});

std::optional<size_t> best = brain.best(bb);                          // nullopt, если все оценки 0
best = brain.best(bb, /*current*/ currentAction, /*stickiness*/ 0.2f); // бонус текущему выбору против «дёрганья»
auto all = brain.scoreAll(bb);                                         // для отладки
```

Кривые (`x` ограничен 0..1, результат тоже):

| `ResponseCurve::Type` | Формула |
| --- | --- |
| `Linear` | `slope·(x − xShift) + yShift` |
| `Polynomial` | `slope·(x − xShift)^exponent + yShift` |
| `Logistic` | `slope / (1 + e^(−10·exponent·(x − 0.5 − xShift))) + yShift` |
| `Logit` | `slope·ln(x′/(1 − x′))/5 + 0.5 + yShift` |

Выбранное действие удобно записать в blackboard и дать дереву поведения его выполнить.

Полный пример: `samples/guide_examples/13-ai/perception_utility.cpp` (`GuideAiUtility`).

## Шаг 9. Восприятие

`PerceptionSystem` хранит слушателей (NPC) и источники (всё, что можно увидеть). Позиции поставляет игра, линию видимости — ваш колбэк (обычно луч физики), шумы — события игры.

```cpp
#include <oxwald/ai/perception.hpp>

PerceptionSystem perception;
perception.setRaycast([&](const glm::vec3& from, const glm::vec3& to) {
    return physicsWorld.raycast(from, to - from, glm::length(to - from)).has_value();   // true = перекрыто
});
perception.setEventCallback([&](PerceptionListenerId l, const PerceivedStimulus& s, bool gained) {
    // заметил / забыл — например, обновить blackboard
});

PerceptionListenerDesc desc;
desc.position = guardPos;
desc.forward = {0, 0, -1};
desc.team = 1;
desc.selfId = guardEntityId;          // себя не воспринимает
desc.sight.range = 20.f;
desc.sight.fovDegrees = 90.f;
desc.sight.forgetAfter = 2.f;
const PerceptionListenerId guard = perception.addListener(desc);

// Каждый кадр (или с интервалом):
perception.setListenerTransform(guard, guardPos, guardForward);
perception.setSource({.id = playerId, .position = playerPos, .team = 2});
perception.reportNoise({.position = shotPos, .loudness = 1.f, .radius = 30.f, .instigator = playerId,
                        .team = 2, .tag = "gunshot"});
perception.update(dt);

if (auto target = perception.bestHostile(guard)) {          // сильнейший враг, зрение в приоритете
    bb.set("target", target->sourceId);
    bb.set("lastKnown", target->lastKnownPosition);          // помнится и после потери из виду
}
perception.canSee(guard, playerId);
perception.knowledgeOf(guard, playerId, Sense::Hearing);    // optional<PerceivedStimulus>
perception.perceived(guard);                                // всё, что знает слушатель
```

| `SightConfig` | По умолчанию | Смысл |
| --- | --- | --- |
| `range`, `fovDegrees` | 20 м, 90° | Основной конус (полный угол) |
| `peripheralFovDegrees`, `peripheralRange` | 160°, 6 м | Периферия: замечает только близких, сила вдвое меньше |
| `loseSightRange` | 25 м | Уже замеченная цель видна до этой дистанции (гистерезис) |
| `eyeHeight`, `targetHeight` | 1.7, 1 м | Точки луча видимости: глаза слушателя → точка на цели |
| `forgetAfter` | 8 с | Сколько помнить последнюю позицию; сила памяти затухает |

| `HearingConfig` | По умолчанию | Смысл |
| --- | --- | --- |
| `rangeMultiplier` | 1 | Множитель радиуса всех шумов («чуткий слух») |
| `threshold` | 0.05 | Минимальная воспринимаемая громкость |
| `useOcclusion`, `occludedFactor` | `true`, 0.4 | Стены (тот же колбэк видимости) ослабляют шум |
| `forgetAfter` | 5 с | Память о шуме |

Громкость шума падает линейно с расстоянием до `radius × rangeMultiplier`. У слуха нет конуса: шум за спиной тоже слышен.

**Команды** (`TeamAttitudes`): одна команда — `Friendly`, разные — `Hostile`, команда 0 нейтральна ко всем. Отношения переопределяются через `perception.attitudes().set(1, 3, Attitude::Friendly)` (по умолчанию симметрично). Что сообщать слушателю, задают поля `detectHostile`/`detectNeutral` (`true`) и `detectFriendly` (`false`). Источник с `visible = false` (невидимость) не виден, но может шуметь.

Полный пример: `samples/guide_examples/13-ai/perception_utility.cpp` (`GuideAiPerception`). Стена в примере — простая функция вместо физики.

## Как это складывается вместе

Типичный кадр NPC:

1. `perception.update(dt)` → `bestHostile` → `blackboard.set("target", …)`.
2. `tree->tick(dt)`: наблюдатели переключают ветки, действия пишут цель движения (`crowd.setTarget`).
3. `cache->update(dt)` (если есть динамические препятствия) → `crowd.update(fixedDt)` в фиксированном шаге.
4. `crowd.position/velocity` → трансформ сущности и параметры анимации ([глава 10](10-animation.md)).

## Типичные ошибки и подводные камни

- **Неправильный порядок обхода треугольников.** Треугольники по часовой стрелке (сверху) считаются «потолком», и навмеш получается пустым. Используйте `addQuad`/`addBox` или проверьте индексы своего меша.
- **Слишком крупный `cellSize`.** Узкие проходы и двери «зарастают». Держите `cellSize` около половины `agentRadius`. Помните, что навмеш сужается на радиус агента: проход шириной 1 м для агента радиусом 0.5 м закрыт.
- **Точка далеко от навмеша.** `findPath`/`nearestPoint` ищут полигон в коробке `setSearchExtents` (по умолчанию ±2 м по XZ, ±4 м по Y). Точка в воздухе выше 4 м даст `Failed`.
- **`Partial` принят за успех.** Проверяйте `status`, а не только `found()`: `Partial` ведёт к ближайшей достижимой точке, а не к цели.
- **Один `NavQuery` на несколько потоков.** Он не потокобезопасен. Создавайте по объекту на поток или систему.
- **Сериализованный тайловый навмеш не пересобирается** без исходной геометрии: после `deserialize` вызывайте `rebuildTiles` с полным `NavMeshInput`. Навмеш `NavTileCache` пока вообще не сериализуется, его строят при загрузке.
- **Забыли `cache->update()`/`flush()`.** Добавленное препятствие появится в навмеше только после обработки очереди.
- **Агент «не слушается» после `setTarget`.** Метод возвращает `false`, если цель не удалось привязать к навмешу. Проверяйте результат.
- **Действие держит ресурс при прерывании.** Если `Action` что-то запустил (движение, анимацию), передайте `onAbort`, иначе при переключении ветки «хвост» останется.
- **`LowerPriority` на глубоком узле.** Прерывание работает для **прямых** детей `Selector`. Условие, вложенное глубже, низкоприоритетные ветки не прервёт.
- **`Wait`/`Timeout` считают и входной тик.** `Wait(0.3)` при тиках по 0.1 с завершится на третьем тике.
- **Тип в blackboard.** `bb.set("count", 5u)` кладёт `u64`, а `get<int32_t>("count")` вернёт `nullopt`. Числовые сравнения в `BlackboardCondition` при этом работают между типами.
- **Производительность восприятия.** Сложность O(слушатели × источники) за `update`. Для больших толп обновляйте слушателей с разнесением по кадрам.
